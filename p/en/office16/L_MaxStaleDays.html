# --- Settings ---
$root = 'HKLM:'   # needs an elevated session

$key = "$root\Software\policies\microsoft\office\16.0\common\officeupdate"

    try   { '{0} = {1}' -f $name, (Get-ItemPropertyValue -Path $key -Name $name -ErrorAction Stop) }
    catch { '{0}: not configured' -f $name }

Admin rights needed: HKLM values require an elevated PowerShell.

Enable

# --- Settings ---
$root = 'HKLM:'   # needs an elevated session

try {
    $key = "$root\Software\policies\microsoft\office\16.0\common\officeupdate"
    if (-not (Test-Path $key)) { New-Item -Path $key -Force -ErrorAction Stop | Out-Null }
    New-ItemProperty -Path $key -Name 'maxstaledays' -PropertyType DWord -Value 1 -Force -ErrorAction Stop | Out-Null   # range 1–90
    'Done.'
}
catch { Write-Error "Failed: $($_.Exception.Message)" }

Microsoft explanation

This policy setting controls the maximum number of days an Office installation can go without being updated before it becomes eligible for Windows Update remediation.

This policy setting does not automatically update users. It only sets the staleness threshold that the Windows Update remediation logic uses when deciding which older Office installations to update.

If you enable this policy setting, you can specify a value from 1 to 3 months. Office installations that have not been updated within the configured number of months will be considered eligible for Windows Update remediation.

If you disable this policy setting, Windows Update remediation will use the default staleness threshold determined by Office.

If you do not configure this policy setting, Windows Update remediation will use the default staleness threshold determined by Office.

Note: This policy setting only applies to Office products that are installed by using Click-to-Run.
