Nicht konfiguriert = der Wert existiert nicht – es gilt der Standard der Anwendung, Benutzer dürfen die Einstellung ändern.

PowerShell

Aktuellen Wert prüfen (nur lesen)

# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

$key = "$root\Software\policies\microsoft\office\16.0\common\ai\contentsafety\specific\texttotable"
foreach ($name in @('allowedselfharmcontent')) {
    try   { '{0} = {1}' -f $name, (Get-ItemPropertyValue -Path $key -Name $name -ErrorAction Stop) }
    catch { '{0}: not configured' -f $name }
}

Adminrechte nötig: HKCU\Software\Policies ist für Standardbenutzer schreibgeschützt. Eine erhöhte Sitzung schreibt in das HKCU des Admins – für einen anderen angemeldeten Benutzer $root auf Registry::HKEY_USERS\<SID> ändern.

Aktivieren

# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

try {
    $key = "$root\Software\policies\microsoft\office\16.0\common\ai\contentsafety\specific\texttotable"
    if (-not (Test-Path $key)) { New-Item -Path $key -Force -ErrorAction Stop | Out-Null }
    New-ItemProperty -Path $key -Name 'allowedselfharmcontent' -PropertyType DWord -Value 0 -Force -ErrorAction Stop | Out-Null   # range 0–7
    'Done.'
}
catch { Write-Error "Failed: $($_.Exception.Message)" }
Auf „Nicht konfiguriert“ zurücksetzen
# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

$key = "$root\Software\policies\microsoft\office\16.0\common\ai\contentsafety\specific\texttotable"
Remove-ItemProperty -Path $key -Name 'allowedselfharmcontent' -ErrorAction SilentlyContinue
'Policy values removed (Not configured).'

Cloud Policy

Cloud Policy (config.office.com → Anpassung → Richtlinienverwaltung) enthält viele Benutzerrichtlinien der Microsoft 365 Apps – suchen nach Allowed severity of self-harm content to and from the Text to Table scenario for the user.. Gilt auch auf nicht verwalteten Geräten und hat Vorrang vor GPO und Intune bei derselben Einstellung.

Erklärung von Microsoft

This local content safety policy setting adjusts the allowed severity of self-harm content to and from the Text to Table scenario for the user. The allowed severity may range from 0 to 7.

0 means allow no self-harm content.

7 means allow all self-harm content.

For more information on content safety severities, please refer to the following documentation:

https://learn.microsoft.com/en-us/azure/ai-services/content-safety/concepts/harm-categories?tabs=definitions

For local content safety policy, scenario-specific settings are prioritized over general settings and computer settings are prioritized over user settings.

If a higher priority policy setting is not configured, then:

- If this policy setting is not configured, the allowed severity of self-harm content to and from the Text to Table scenario is determined by lower priority policy settings.

- If this policy setting is not configured and lower priority policy settings are also not configured, the allowed severity of self-harm content to and from the Text to Table scenario defaults to 2.

For this policy setting, the order of priority is:

1. Allowed severity of self-harm content to and from the Text to Table scenario for the computer.

2. Allowed severity of self-harm content in general for the computer.

3. Allowed severity of self-harm content to and from the Text to Table scenario for the user.

4. Allowed severity of self-harm content in general for the user.
