Nicht konfiguriert = der Wert existiert nicht – es gilt der Standard der Anwendung, Benutzer dürfen die Einstellung ändern.

PowerShell

Aktuellen Wert prüfen (nur lesen)

# --- Settings ---
$root = 'HKLM:'   # needs an elevated session

$key = "$root\Software\policies\microsoft\office\16.0\common\licensing"
foreach ($name in @('sclcacheoverride', 'sclcacheoverridedirectory')) {
    try   { '{0} = {1}' -f $name, (Get-ItemPropertyValue -Path $key -Name $name -ErrorAction Stop) }
    catch { '{0}: not configured' -f $name }
}

Adminrechte nötig: HKLM-Werte brauchen eine PowerShell mit erhöhten Rechten.

Aktivieren

# --- Settings ---
$root = 'HKLM:'   # needs an elevated session

try {
    $key = "$root\Software\policies\microsoft\office\16.0\common\licensing"
    if (-not (Test-Path $key)) { New-Item -Path $key -Force -ErrorAction Stop | Out-Null }
    New-ItemProperty -Path $key -Name 'sclcacheoverride' -PropertyType DWord -Value 1 -Force -ErrorAction Stop | Out-Null   # Enabled
    New-ItemProperty -Path $key -Name 'sclcacheoverridedirectory' -PropertyType String -Value '<value>' -Force -ErrorAction Stop | Out-Null   # your value
    'Done.'
}
catch { Write-Error "Failed: $($_.Exception.Message)" }
Deaktivieren
# --- Settings ---
$root = 'HKLM:'   # needs an elevated session

try {
    $key = "$root\Software\policies\microsoft\office\16.0\common\licensing"
    if (-not (Test-Path $key)) { New-Item -Path $key -Force -ErrorAction Stop | Out-Null }
    New-ItemProperty -Path $key -Name 'sclcacheoverride' -PropertyType DWord -Value 0 -Force -ErrorAction Stop | Out-Null   # Disabled
    'Done.'
}
catch { Write-Error "Failed: $($_.Exception.Message)" }
Auf „Nicht konfiguriert“ zurücksetzen
# --- Settings ---
$root = 'HKLM:'   # needs an elevated session

$key = "$root\Software\policies\microsoft\office\16.0\common\licensing"
Remove-ItemProperty -Path $key -Name 'sclcacheoverride', 'sclcacheoverridedirectory' -ErrorAction SilentlyContinue
'Policy values removed (Not configured).'

Erklärung von Microsoft

Diese Richtlinieneinstellung erlaubt es Ihnen, den Dateiordner zum Speichern des Lizenzierungstokens anzugeben, das von der Aktivierung gemeinsam genutzter Computer verwendet wird.

Die Aktivierung gemeinsam genutzter Computer wird nur in Situationen verwendet, in denen mehrere Benutzer denselben Computer nutzen. Beispielsweise wenn Remotedesktopdienste (RDS) verwendet werden.

Standardmäßig wird das von der Aktivierung gemeinsam genutzter Computer verwendete Lizenzierungstoken im Ordner "%localappdata%\Microsoft\Office\16.0\Licensing" gespeichert. Dieser Speicherort ist aber nicht im Roamingprofil des Benutzers enthalten, weshalb das Lizenzierungstoken nicht verfügbar ist, wenn sich der Benutzer bei einem anderen Computer anmeldet.

Wenn Sie diese Richtlinieneinstellung aktivieren, müssen Sie einen Speicherort angeben, wo das Lizenzierungstoken gespeichert werden soll, das von der Aktivierung gemeinsam genutzter Computer verwendet wird. Sie sollten einen Ordner angeben, der für den Benutzer spezifisch ist und der für diesen von jedem Computer im Netzwerk aus verfügbar ist, bei dem sich der Benutzer anmeldet. Beispielsweise ein Ordner, der im Roamingprofil des Benutzers enthalten ist, oder ein freigegebener Ordner im Netzwerk, wenn für jeden Benutzer ein solcher Ordner vorhanden ist.

Wenn Sie diese Richtlinieneinstellung deaktivieren oder nicht konfigurieren, verwendet Office den Standardordner zum Speichern des Lizenzierungstokens, das von der Aktivierung gemeinsam genutzter Computer verwendet wird.

Hinweis: Diese Richtlinieneinstellung gilt nur für Abonnementpläne, die Microsoft 365 Apps for Enterprise umfassen, sowie für Abonnementversionen von Project und Visio.​
