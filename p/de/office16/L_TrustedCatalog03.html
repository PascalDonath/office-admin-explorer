Registrierung

WertDaten
HKCU\Software\policies\microsoft\office\16.0\wef\trustedcatalogs\catalog03
urltext

Nicht konfiguriert = der Wert existiert nicht – es gilt der Standard der Anwendung, Benutzer dürfen die Einstellung ändern.

PowerShell

Aktuellen Wert prüfen (nur lesen)

# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

$key = "$root\Software\policies\microsoft\office\16.0\wef\trustedcatalogs\catalog03"
foreach ($name in @('url')) {
    try   { '{0} = {1}' -f $name, (Get-ItemPropertyValue -Path $key -Name $name -ErrorAction Stop) }
    catch { '{0}: not configured' -f $name }
}

Adminrechte nötig: HKCU\Software\Policies ist für Standardbenutzer schreibgeschützt. Eine erhöhte Sitzung schreibt in das HKCU des Admins – für einen anderen angemeldeten Benutzer $root auf Registry::HKEY_USERS\<SID> ändern.

Aktivieren

# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

try {
    $key = "$root\Software\policies\microsoft\office\16.0\wef\trustedcatalogs\catalog03"
    if (-not (Test-Path $key)) { New-Item -Path $key -Force -ErrorAction Stop | Out-Null }
    New-ItemProperty -Path $key -Name 'url' -PropertyType String -Value '<value>' -Force -ErrorAction Stop | Out-Null   # your value
    'Done.'
}
catch { Write-Error "Failed: $($_.Exception.Message)" }
Auf „Nicht konfiguriert“ zurücksetzen
# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

$key = "$root\Software\policies\microsoft\office\16.0\wef\trustedcatalogs\catalog03"
Remove-ItemProperty -Path $key -Name 'url' -ErrorAction SilentlyContinue
'Policy values removed (Not configured).'

Cloud Policy

Cloud Policy (config.office.com → Anpassung → Richtlinienverwaltung) enthält viele Benutzerrichtlinien der Microsoft 365 Apps – suchen nach Trusted Catalog Location #3. Gilt auch auf nicht verwalteten Geräten und hat Vorrang vor GPO und Intune bei derselben Einstellung.

Erklärung von Microsoft

Mit dieser Richtlinieneinstellung wird der URL-Speicherort eines vertrauenswürdigen SharePoint-Katalogs oder freigegebenen Ordnerkatalogs festgelegt. Alle Web-Add-Ins an diesem Speicherort sind vertrauenswürdig, damit die Benutzer*innen mit diesen Add-Ins in ihren Dokumenten arbeiten können. Sie können diese Add-Ins jedoch nicht in ein Office-Dokument einfügen.

Wenn Sie diese Richtlinieneinstellung aktivieren und die URL festlegen, können Benutzer*innen mit Web-Add-Ins aus dem SharePoint-Katalog oder dem freigegebenen Ordnerkatalog unter dieser URL arbeiten. Falls die Richtlinie, über die Benutzer*innen die Kontrolle über die vertrauenswürdigen freigegebenen Ordnerkataloge gestattet wird, aktiviert ist, werden freigegebene Ordnerkataloge unter dieser URL ignoriert.

Wenn Sie diese Richtlinieneinstellung deaktivieren, können Benutzer*innen nicht mit Web-Add-Ins in Internetzonenkatalogen arbeiten, und es wird eine Aufforderung angezeigt, bevor sie Web-Add-Ins aus anderen Katalogen starten. Falls die Richtlinie, über die Benutzer*innen die Kontrolle über die vertrauenswürdigen freigegebenen Ordnerkataloge gestattet wird, aktiviert ist, können Benutzer*innen ihre eigenen Speicherorte für vertrauenswürdige freigegebene Ordnerkataloge festlegen. Web-Add-Ins an den Speicherorten der vertrauenswürdigen Kataloge werden außerdem ohne Nachfrage zur Vertrauensstellung gestartet.

Wenn Sie diese Richtlinieneinstellung oder andere Richtlinieneinstellungen im Ordner "Vertrauenswürdige Kataloge" nicht konfigurieren, können Benutzer*innen ihre eigenen Speicherorte für den vertrauenswürdigen SharePoint-Katalog und den freigegebenen Ordnerkatalog festlegen.
