Registrierung

WertDaten
HKCU\Software\policies\microsoft\office\16.0\excel\security
extensionhardening0 = Allow different · 1 = Allow different, but warn · 2 = Always match file type

Nicht konfiguriert = der Wert existiert nicht – es gilt der Standard der Anwendung, Benutzer dürfen die Einstellung ändern.

PowerShell

Aktuellen Wert prüfen (nur lesen)

# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

$key = "$root\Software\policies\microsoft\office\16.0\excel\security"
foreach ($name in @('extensionhardening')) {
    try   { '{0} = {1}' -f $name, (Get-ItemPropertyValue -Path $key -Name $name -ErrorAction Stop) }
    catch { '{0}: not configured' -f $name }
}

Adminrechte nötig: HKCU\Software\Policies ist für Standardbenutzer schreibgeschützt. Eine erhöhte Sitzung schreibt in das HKCU des Admins – für einen anderen angemeldeten Benutzer $root auf Registry::HKEY_USERS\<SID> ändern.

Aktivieren

# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

try {
    $key = "$root\Software\policies\microsoft\office\16.0\excel\security"
    if (-not (Test-Path $key)) { New-Item -Path $key -Force -ErrorAction Stop | Out-Null }
    New-ItemProperty -Path $key -Name 'extensionhardening' -PropertyType DWord -Value 0 -Force -ErrorAction Stop | Out-Null   # options: 0 = Allow different, 1 = Allow different, but warn, 2 = Always match file type
    'Done.'
}
catch { Write-Error "Failed: $($_.Exception.Message)" }
Auf „Nicht konfiguriert“ zurücksetzen
# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

$key = "$root\Software\policies\microsoft\office\16.0\excel\security"
Remove-ItemProperty -Path $key -Name 'extensionhardening' -ErrorAction SilentlyContinue
'Policy values removed (Not configured).'

Cloud Policy

Cloud Policy (config.office.com → Anpassung → Richtlinienverwaltung) enthält viele Benutzerrichtlinien der Microsoft 365 Apps – suchen nach Force file extension to match file type. Gilt auch auf nicht verwalteten Geräten und hat Vorrang vor GPO und Intune bei derselben Einstellung.

Erklärung von Microsoft

Diese Richtlinieneinstellung steuert, wie Excel Dateitypen lädt, die nicht ihrer Erweiterung entsprechen. Excel kann Dateien mit Erweiterungen laden, die nicht mit dem Typ der Dateien übereinstimmen. Wenn z. B. eine Datei mit kommagetrennten Werten (CSV) mit dem Namen "beispiel.csv" in "beispiel.xls" (oder eine andere Dateierweiterung, die nur von Excel 2003 oder früher unterstützt wird) umbenannt wird, kann Excel die Datei ordnungsgemäß als CSV-Datei laden.

Wenn Sie diese Richtlinieneinstellung aktivieren, können Sie unter drei Optionen für das Arbeiten mit Dateien, die nicht übereinstimmende Erweiterungen aufweisen, wählen:

- Andere zulassen - Excel öffnet die Dateien ordnungsgemäß, ohne Benutzer zu warnen, dass die Dateien Erweiterungen aufweisen, die nicht zum Inhalt passen. Wenn die Benutzer die Dateien anschließend bearbeiten und speichern, behält Excel sowohl das eigentliche, zugrundeliegende Dateiformat als auch die nicht ordnungsgemäße Dateierweiterung bei.

- Andere zulassen, aber warnen - Excel öffnet die Dateien ordnungsgemäß, warnt die Benutzer jedoch wegen des nicht übereinstimmenden Dateityps. Diese Option stellt die Standardkonfiguration in Excel dar.

- Immer Übereinstimmung mit Dateityp - Excel öffnet keine Dateien, die nicht übereinstimmende Dateierweiterungen aufweisen.

Wenn Sie diese Richtlinieneinstellung deaktivieren oder nicht konfigurieren, öffnet Excel Dateien, wenn Benutzer versuchen, Dateien mit falscher Erweiterung zu öffnen, zeigt aber eine Warnung an, dass der Dateityp nicht der von Excel erwartete ist.
