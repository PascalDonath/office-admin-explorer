Pfad der Gruppenrichtlinie

Benutzerkonfiguration\Richtlinien\Administrative Vorlagen\Microsoft Excel 2016\Excel-Optionen\Sicherheit\Trust Center\Vertrauenswürdige Speicherorte
User Configuration\Policies\Administrative Templates\Microsoft Excel 2016\Excel Options\Security\Trust Center\Trusted Locations

Registrierung

WertDaten
HKCU\Software\policies\microsoft\office\16.0\excel\security\trusted locations
allownetworklocationsEnabled = 1 · Disabled = 0

Nicht konfiguriert = der Wert existiert nicht – es gilt der Standard der Anwendung, Benutzer dürfen die Einstellung ändern.

PowerShell

Aktuellen Wert prüfen (nur lesen)

# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

$key = "$root\Software\policies\microsoft\office\16.0\excel\security\trusted locations"
foreach ($name in @('allownetworklocations')) {
    try   { '{0} = {1}' -f $name, (Get-ItemPropertyValue -Path $key -Name $name -ErrorAction Stop) }
    catch { '{0}: not configured' -f $name }
}

Adminrechte nötig: HKCU\Software\Policies ist für Standardbenutzer schreibgeschützt. Eine erhöhte Sitzung schreibt in das HKCU des Admins – für einen anderen angemeldeten Benutzer $root auf Registry::HKEY_USERS\<SID> ändern.

Aktivieren

# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

try {
    $key = "$root\Software\policies\microsoft\office\16.0\excel\security\trusted locations"
    if (-not (Test-Path $key)) { New-Item -Path $key -Force -ErrorAction Stop | Out-Null }
    New-ItemProperty -Path $key -Name 'allownetworklocations' -PropertyType DWord -Value 1 -Force -ErrorAction Stop | Out-Null   # Enabled
    'Done.'
}
catch { Write-Error "Failed: $($_.Exception.Message)" }
Deaktivieren
# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

try {
    $key = "$root\Software\policies\microsoft\office\16.0\excel\security\trusted locations"
    if (-not (Test-Path $key)) { New-Item -Path $key -Force -ErrorAction Stop | Out-Null }
    New-ItemProperty -Path $key -Name 'allownetworklocations' -PropertyType DWord -Value 0 -Force -ErrorAction Stop | Out-Null   # Disabled
    'Done.'
}
catch { Write-Error "Failed: $($_.Exception.Message)" }
Auf „Nicht konfiguriert“ zurücksetzen
# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

$key = "$root\Software\policies\microsoft\office\16.0\excel\security\trusted locations"
Remove-ItemProperty -Path $key -Name 'allownetworklocations' -ErrorAction SilentlyContinue
'Policy values removed (Not configured).'

Cloud Policy

Cloud Policy (config.office.com → Anpassung → Richtlinienverwaltung) enthält viele Benutzerrichtlinien der Microsoft 365 Apps – suchen nach Allow Trusted Locations on the network. Gilt auch auf nicht verwalteten Geräten und hat Vorrang vor GPO und Intune bei derselben Einstellung.

Erklärung von Microsoft

Diese Richtlinieneinstellung steuert, ob vertrauenswürdige Speicherorte im Netzwerk verwendet werden können.

Wenn Sie diese Richtlinieneinstellung aktivieren, können Benutzer vertrauenswürdige Speicherorte auf Netzwerkfreigaben oder an anderen Remotespeicherorten angeben, die nicht ihrer direkten Kontrolle unterstehen, indem sie im Abschnitt "Vertrauenswürdige Speicherorte" im Trust Center auf die Schaltfläche "Neuen Speicherort hinzufügen" klicken. Das Laden von Inhalten, Code und Add-Ins wird von vertrauenswürdigen Speicherorten mit minimaler Sicherheit und ohne Aufforderung des Benutzers zur Genehmigung zugelassen.

Wenn Sie diese Richtlinieneinstellung deaktivieren, ignoriert die ausgewählte Anwendung alle im Abschnitt "Vertrauenswürdige Speicherorte" im Trust Center aufgelisteten Netzwerkspeicherorte.

Wenn Sie vertrauenswürdige Speicherorte außerdem mithilfe von Gruppenrichtlinien bereitstellen, sollten Sie prüfen, ob sie sich teilweise an Remotespeicherorten befinden. Wenn Remotespeicherorte vorhanden sind, und Sie Remotespeicherorte nicht mithilfe dieser Richtlinieneinstellung zulassen, werden die Richtlinienschlüssel, die auf Remotespeicherorte verweisen, auf Clientcomputern ignoriert.

Durch das Deaktivieren dieser Richtlinieneinstellung werden keine Netzwerkspeicherorte aus der Liste "Vertrauenswürdige Speicherorte" gelöscht, jedoch treten für Benutzer, die der Liste "Vertrauenswürdige Speicherorte" Netzwerkspeicherorte hinzufügen, Unterbrechungen auf. Es wird empfohlen, diese Richtlinieneinstellung nicht zu aktivieren (worauf das Kontrollkästchen "Vertrauenswürdige Speicherorte im Netzwerk zulassen (nicht empfohlen)" bereits hinweist). Daher sollte es in der Praxis unter den meisten Umständen möglich sein, diese Richtlinieneinstellung zu deaktivieren, ohne nennenswerte Einschränkungen der Nutzbarkeit für die meisten Benutzer hervorzurufen.

Wenn Sie diese Richtlinieneinstellung nicht aktivieren, können Benutzer das Kontrollkästchen "Vertrauenswürdige Speicherorte im Netzwerk zulassen (nicht empfohlen)" auf Wunsch aktivieren und dann vertrauenswürdige Speicherorte durch Klicken auf die Schaltfläche "Neuen Speicherort hinzufügen" angeben.
