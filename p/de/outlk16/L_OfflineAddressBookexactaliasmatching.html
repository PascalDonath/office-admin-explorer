Office Admin Explorer › Richtlinien › outlk16.admx › Offlineadressbuch

E-Mail-Alias zurückgeben, falls er genau mit der bei der Suche im Offlineadressbuch eingegebenen E-Mail-Adresse übereinstimmt

Nur klassisches Outlook. Das neue Outlook für Windows ignoriert die meisten dieser Office-Richtlinien – es wird stattdessen über Exchange Online (OWA-Postfachrichtlinie) gesteuert.

Registrierung

WertDaten
HKCU\Software\policies\microsoft\exchange\exchange provider
oab exact alias matchEnabled = 1 · Disabled = 0

Nicht konfiguriert = der Wert existiert nicht – es gilt der Standard der Anwendung, Benutzer dürfen die Einstellung ändern.

PowerShell

Aktuellen Wert prüfen (nur lesen)

# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

$key = "$root\Software\policies\microsoft\exchange\exchange provider"
foreach ($name in @('oab exact alias match')) {
    try   { '{0} = {1}' -f $name, (Get-ItemPropertyValue -Path $key -Name $name -ErrorAction Stop) }
    catch { '{0}: not configured' -f $name }
}

Adminrechte nötig: HKCU\Software\Policies ist für Standardbenutzer schreibgeschützt. Eine erhöhte Sitzung schreibt in das HKCU des Admins – für einen anderen angemeldeten Benutzer $root auf Registry::HKEY_USERS\<SID> ändern.

Aktivieren

# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

try {
    $key = "$root\Software\policies\microsoft\exchange\exchange provider"
    if (-not (Test-Path $key)) { New-Item -Path $key -Force -ErrorAction Stop | Out-Null }
    New-ItemProperty -Path $key -Name 'oab exact alias match' -PropertyType DWord -Value 1 -Force -ErrorAction Stop | Out-Null   # Enabled
    'Done.'
}
catch { Write-Error "Failed: $($_.Exception.Message)" }
Deaktivieren
# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

try {
    $key = "$root\Software\policies\microsoft\exchange\exchange provider"
    if (-not (Test-Path $key)) { New-Item -Path $key -Force -ErrorAction Stop | Out-Null }
    New-ItemProperty -Path $key -Name 'oab exact alias match' -PropertyType DWord -Value 0 -Force -ErrorAction Stop | Out-Null   # Disabled
    'Done.'
}
catch { Write-Error "Failed: $($_.Exception.Message)" }
Auf „Nicht konfiguriert“ zurücksetzen
# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

$key = "$root\Software\policies\microsoft\exchange\exchange provider"
Remove-ItemProperty -Path $key -Name 'oab exact alias match' -ErrorAction SilentlyContinue
'Policy values removed (Not configured).'

Cloud Policy

Cloud Policy (config.office.com → Anpassung → Richtlinienverwaltung) enthält viele Benutzerrichtlinien der Microsoft 365 Apps – suchen nach Return e-mail alias if it exactly matches the provided e-mail address when searching OAB. Gilt auch auf nicht verwalteten Geräten und hat Vorrang vor GPO und Intune bei derselben Einstellung.

Erklärung von Microsoft

Wenn Sie das Offlineadressbuch durchsuchen, werden E-Mail-Adressen von Outlook standardmäßig mithilfe der Auflösung mehrdeutiger Namen aufgelöst. Mit der Auflösung mehrdeutiger Namen schlägt Outlook zusätzliche mögliche Übereinstimmungen vor (soweit vorhanden), selbst wenn ein Name vorhanden ist, der genau mit dem eingegebenen E-Mail-Alias übereinstimmt. Wenn Sie diese Einstellung aktivieren, können Sie das Verhalten ändern, sodass von Outlook eine einzige E-Mail-Adresse zurückgegeben wird, falls sie genau mit einem E-Mail-Alias übereinstimmt.
