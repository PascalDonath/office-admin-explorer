Als Ebene 2 blockierte Dateierweiterungen entfernen

Nur klassisches Outlook. Das neue Outlook für Windows ignoriert die meisten dieser Office-Richtlinien – es wird stattdessen über Exchange Online (OWA-Postfachrichtlinie) gesteuert.

Registrierung

fileextensionsremovelevel2text

Nicht konfiguriert = der Wert existiert nicht – es gilt der Standard der Anwendung, Benutzer dürfen die Einstellung ändern.

PowerShell

Aktuellen Wert prüfen (nur lesen)

# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

$key = "$root\Software\policies\microsoft\office\16.0\outlook\security"
foreach ($name in @('fileextensionsremovelevel2')) {
    try   { '{0} = {1}' -f $name, (Get-ItemPropertyValue -Path $key -Name $name -ErrorAction Stop) }
    catch { '{0}: not configured' -f $name }
}

Adminrechte nötig: HKCU\Software\Policies ist für Standardbenutzer schreibgeschützt. Eine erhöhte Sitzung schreibt in das HKCU des Admins – für einen anderen angemeldeten Benutzer $root auf Registry::HKEY_USERS\<SID> ändern.

Aktivieren

# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

try {
    $key = "$root\Software\policies\microsoft\office\16.0\outlook\security"
    if (-not (Test-Path $key)) { New-Item -Path $key -Force -ErrorAction Stop | Out-Null }
    New-ItemProperty -Path $key -Name 'fileextensionsremovelevel2' -PropertyType String -Value '<value>' -Force -ErrorAction Stop | Out-Null   # your value
    'Done.'
}
catch { Write-Error "Failed: $($_.Exception.Message)" }
Auf „Nicht konfiguriert“ zurücksetzen
# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

$key = "$root\Software\policies\microsoft\office\16.0\outlook\security"
Remove-ItemProperty -Path $key -Name 'fileextensionsremovelevel2' -ErrorAction SilentlyContinue
'Policy values removed (Not configured).'

Cloud Policy

Cloud Policy (config.office.com → Anpassung → Richtlinienverwaltung) enthält viele Benutzerrichtlinien der Microsoft 365 Apps – suchen nach Remove file extensions blocked as Level 2. Gilt auch auf nicht verwalteten Geräten und hat Vorrang vor GPO und Intune bei derselben Einstellung.

Erklärung von Microsoft

Diese Richtlinieneinstellung steuert, welche Anlagentypen (anhand der Dateierweiterung) auf einem Datenträger gespeichert werden müssen, bevor sie von Benutzern geöffnet werden können. Dateien mit bestimmten Erweiterungen können der Kategorie "Ebene 1" (Benutzer können die Datei nicht anzeigen) oder der "Ebene 2" (Benutzer können die Datei öffnen, nachdem sie auf einem Datenträger gespeichert wurde) zugeordnet werden. Benutzer können Dateien uneingeschränkt öffnen, die nicht den Kategorien "Ebene 1" oder "Ebene 2" zugeordnet wurden.

Wenn Sie diese Richtlinieneinstellung aktivieren, können Sie eine Liste der Anlagendateitypen angeben, die als "Ebene 2" klassifiziert werden. In diesem Fall müssen Benutzer aktiv entscheiden, die Anlage herunterzuladen, damit sie sie anzeigen können.

Wenn Sie diese Richtlinieneinstellung deaktivieren oder nicht konfigurieren, klassifiziert Outlook keine Dateityperweiterungen als "Ebene 2".

Wichtig: Diese Richtlinieneinstellung wird nur verwendet, wenn die Richtlinieneinstellung "Outlook-Sicherheitsmodus" unter "Microsoft Outlook 2016\Sicherheit\Sicherheitsformulareinstellungen" auf "Outlook-Sicherheitsgruppenrichtlinie verwenden" festgelegt ist.
