SharePoint-Synchronisierungsanfragen und -antworten protokollieren

Nur klassisches Outlook. Das neue Outlook für Windows ignoriert die meisten dieser Office-Richtlinien – es wird stattdessen über Exchange Online (OWA-Postfachrichtlinie) gesteuert.

Registrierung

WertDaten
HKCU\Software\policies\microsoft\office\16.0\outlook\options\mail
enablewsssyncloggingEnabled = 1 · Disabled = 0

Nicht konfiguriert = der Wert existiert nicht – es gilt der Standard der Anwendung, Benutzer dürfen die Einstellung ändern.

PowerShell

Aktuellen Wert prüfen (nur lesen)

# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

$key = "$root\Software\policies\microsoft\office\16.0\outlook\options\mail"
foreach ($name in @('enablewsssynclogging')) {
    try   { '{0} = {1}' -f $name, (Get-ItemPropertyValue -Path $key -Name $name -ErrorAction Stop) }
    catch { '{0}: not configured' -f $name }
}

Adminrechte nötig: HKCU\Software\Policies ist für Standardbenutzer schreibgeschützt. Eine erhöhte Sitzung schreibt in das HKCU des Admins – für einen anderen angemeldeten Benutzer $root auf Registry::HKEY_USERS\<SID> ändern.

Aktivieren

# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

try {
    $key = "$root\Software\policies\microsoft\office\16.0\outlook\options\mail"
    if (-not (Test-Path $key)) { New-Item -Path $key -Force -ErrorAction Stop | Out-Null }
    New-ItemProperty -Path $key -Name 'enablewsssynclogging' -PropertyType DWord -Value 1 -Force -ErrorAction Stop | Out-Null   # Enabled
    'Done.'
}
catch { Write-Error "Failed: $($_.Exception.Message)" }
Deaktivieren
# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

try {
    $key = "$root\Software\policies\microsoft\office\16.0\outlook\options\mail"
    if (-not (Test-Path $key)) { New-Item -Path $key -Force -ErrorAction Stop | Out-Null }
    New-ItemProperty -Path $key -Name 'enablewsssynclogging' -PropertyType DWord -Value 0 -Force -ErrorAction Stop | Out-Null   # Disabled
    'Done.'
}
catch { Write-Error "Failed: $($_.Exception.Message)" }
Auf „Nicht konfiguriert“ zurücksetzen
# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

$key = "$root\Software\policies\microsoft\office\16.0\outlook\options\mail"
Remove-ItemProperty -Path $key -Name 'enablewsssynclogging' -ErrorAction SilentlyContinue
'Policy values removed (Not configured).'

Cloud Policy

Cloud Policy (config.office.com → Anpassung → Richtlinienverwaltung) enthält viele Benutzerrichtlinien der Microsoft 365 Apps – suchen nach Log SharePoint sync requests and responses. Gilt auch auf nicht verwalteten Geräten und hat Vorrang vor GPO und Intune bei derselben Einstellung.

Erklärung von Microsoft

Diese Richtlinieneinstellung ermöglicht Ihnen die Steuerung, ob Synchronisierungsanfragen und -antworten zwischen Outlook und SharePoint protokolliert werden. Protokolldateien können bei der Diagnose von Problemen mit der Interaktion zwischen Outlook und SharePoint hilfreich sein. Jede Protokolldatei ist mit mindestens einer XML-Datei verknüpft (ebenfalls im TEMP-Verzeichnis), die detaillierte Informationen zu Serverantworten und Fehlern enthält. Der XML-Dateiname basiert auf der entsprechenden Protokolldatei. Sie können alle zusammengehörigen Diagnosedateien abrufen, indem Sie alle "*-wss-*.*"-Dateien aus dem TEMP-Verzeichnis kopieren.

Wenn Sie diese Richtlinieneinstellung aktivieren, werden die meisten Synchronisierungsanfrage und -antworten von Outlook in einer Protokolldatei im TEMP-Verzeichnis des Benutzers protokolliert. Pro Sitzung wird eine Protokolldatei erstellt (bis zu sieben insgesamt), wobei die Namenskonvention "0-wss-sync-log.HTM", "1-wss-sync-log.HTM" usw. verwendet wird.

Wenn Sie diese Richtlinieneinstellung deaktivieren oder nicht konfigurieren, werden Synchronisierungsanfragen und -antworten zwischen Outlook und SharePoint nicht protokolliert.
