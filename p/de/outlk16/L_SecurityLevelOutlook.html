Nicht konfiguriert = der Wert existiert nicht – es gilt der Standard der Anwendung, Benutzer dürfen die Einstellung ändern.

PowerShell

Aktuellen Wert prüfen (nur lesen)

# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

$key = "$root\Software\policies\microsoft\office\16.0\outlook\security"
foreach ($name in @('level')) {
    try   { '{0} = {1}' -f $name, (Get-ItemPropertyValue -Path $key -Name $name -ErrorAction Stop) }
    catch { '{0}: not configured' -f $name }
}

Adminrechte nötig: HKCU\Software\Policies ist für Standardbenutzer schreibgeschützt. Eine erhöhte Sitzung schreibt in das HKCU des Admins – für einen anderen angemeldeten Benutzer $root auf Registry::HKEY_USERS\<SID> ändern.

Aktivieren

# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

try {
    $key = "$root\Software\policies\microsoft\office\16.0\outlook\security"
    if (-not (Test-Path $key)) { New-Item -Path $key -Force -ErrorAction Stop | Out-Null }
    New-ItemProperty -Path $key -Name 'level' -PropertyType DWord -Value 2 -Force -ErrorAction Stop | Out-Null   # options: 2 = Always warn, 4 = Never warn, disable all, 3 = Warn for signed, disable unsigned, 1 = No security check
    'Done.'
}
catch { Write-Error "Failed: $($_.Exception.Message)" }
Auf „Nicht konfiguriert“ zurücksetzen
# --- Settings ---
$root = 'HKCU:'   # other signed-in user (elevated): 'Registry::HKEY_USERS\<SID>'

$key = "$root\Software\policies\microsoft\office\16.0\outlook\security"
Remove-ItemProperty -Path $key -Name 'level' -ErrorAction SilentlyContinue
'Policy values removed (Not configured).'

Erklärung von Microsoft

Diese Richtlinieneinstellung steuert die Sicherheitsstufe für Makros in Outlook.

Wenn Sie diese Richtlinieneinstellung aktivieren, können Sie aus vier Optionen für die Behandlung von Makros in Outlook auswählen:

– „Immer warnen“: Diese Option entspricht der Option „Benachrichtigungen für alle Makros“ im Abschnitt „Makroeinstellungen“ im Outlook Trust Center. Outlook deaktiviert alle Makros, die nicht von einem vertrauenswürdigen Speicherort aus geöffnet werden, auch wenn die Makros von einem vertrauenswürdigen Herausgeber signiert sind. Für jedes deaktivierte Makro zeigt Outlook ein Dialogfeld mit einer Sicherheitswarnung an, das Informationen über das Makro und seine digitale Signatur (falls vorhanden) enthält, und ermöglicht den Benutzern, das Makro zu aktivieren oder es deaktiviert zu lassen.

– „Nie warnen, alle deaktivieren“: Diese Option entspricht der Option „Alle Makros ohne Benachrichtigung deaktivieren“ im Trust Center. Outlook deaktiviert alle Makros, die nicht von vertrauenswürdigen Speicherorten aus geöffnet werden, und benachrichtigt den Benutzer nicht.

– „Warnung bei signierten, nicht signierte deaktivieren“: Diese Option entspricht der Option „Benachrichtigungen für digital signierte Makros, alle anderen Makros deaktivieren“ im Trust Center. Outlook behandelt Makros wie folgt:

-- Wenn ein Makro von einem vertrauenswürdigen Herausgeber digital signiert ist, kann das Makro ausgeführt werden, wenn der Benutzer dem Herausgeber bereits vertraut hat.

-- Wenn ein Makro eine gültige Signatur eines Herausgebers hat, dem der Benutzer nicht vertraut hat, kann der Benutzer im Dialogfeld der Sicherheitswarnung für das Makro auswählen, ob das Makro für die aktuelle Sitzung aktiviert oder deaktiviert werden soll, oder ob der Herausgebers zur Liste der vertrauenswürdigen Herausgeber hinzugefügt werden soll, damit das Macro in Zukunft ohne Aufforderung des Benutzers ausgeführt wird.

-- Wenn ein Makro keine gültige Signatur besitzt, deaktiviert Outlook dieses, ohne den Benutzer dazu aufzufordern, es sei denn, es wird von einem vertrauenswürdigen Speicherort aus geöffnet.

Diese Option ist die Standardkonfiguration in Outlook.

– „Keine Sicherheitsprüfung“: Diese Option entspricht der Option „Alle Makros aktivieren (nicht empfohlen; möglicherweise gefährlicher Code kann ausgeführt werden)“ im Trust Center. Outlook führt alle Makros aus, ohne die Benutzer dazu aufzufordern. Diese Konfiguration macht die Computer der Benutzer anfällig für potenziell schädlichen Code und wird nicht empfohlen.

Wenn Sie diese Richtlinieneinstellung deaktivieren oder nicht konfigurieren, entspricht das Verhalten der Option „Warnung bei signierten, nicht signierte deaktivieren“.
